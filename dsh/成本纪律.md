# 成本纪律 —— agent-toolkit 的 dsh/ 区专用

本目录 `dsh/` 放 **DSH 专用**工具与规则 ✓（通用工具在 `../tools/` ✗ 不要混进来）

## 通用纪律（继承 agent-toolkit）

1. **数值必须有来历**：`依据: 实测 …` / `依据: 机制 …` / `依据: 未实测 …`（三态之一 ✓）
2. **脚本卫生**：所有 `.py` 必须能编译 ✓；路径不写反斜杠字面量 ✓；打印非 ASCII 要加 UTF-8 兜底 ✓
3. **改代码前先写方案**；**收工前自检全绿**：

```bash
python dsh\tools\session-cost\test_session_cost.py
python ..\tools\script-hygiene\hygiene_check.py --root .
python ..\tools\provenance\provenance_check.py --root . --audit
```

## ★ 轮次成本纪律（本目录特有，2026-10-16 由实测得出）

### 事实（实测，不是推测 ✓）

| 事实 | 数值 |
|---|---|
| 会话成本当量的主要来源 | **缓存读 ≈ 90%**（= 步数 × 上下文大小 ✗）|
| 单步都会重读一遍上下文 | 轮 26 用了 **131 步** ⇒ 4958 万 token ✗ |
| "前缀缓存整段作废"的代价 | ≈ **当前上下文的全额重发** ✗（轮 151 步 6 = 66.9 万 ✗）|
| 输出的占比 | token 0.2% ｜ 成本当量 ~6.5% ⇒ **几乎不是问题** ✓ |
| 缓存 TTL | 实测 > 48 秒（步 19→20 间隔 48 秒后仍命中 ✓）|

### 会触发"前缀作废"的动作（实测归因）

| 触发 | 事件 | 代价 |
|---|---|---|
| **改动工作区配置类文件**（`AGENTS.md`、`.gitattributes`、项目根配置等）| `system/message` source=`system-prompt` ✗ | ≈ 当前上下文**全额**重发 ✗ |
| 自动检查点（compaction）| 注入压缩摘要 ✓ | 一笔全额重发（但会把上下文压小 ✓）|
| 工作区指令更新 | `agent-instructions` 注入 | 只重发增量 ✓（便宜 ✓）|

### 要改的习惯（**可判定**的触发条件，不是"注意一点" ✗）

动手前按这三条自检 ✓：

1. **我要改"工作区配置类文件"吗？**（`AGENTS.md` / `.gitattributes` / 项目根配置 ✓）
   - 会 ⇒ 这会让系统提示重建 ⇒ **等于把当前上下文全额重发一次** ✗
   - **动作**：先看当前上下文规模（`session_cost.py --turns` ✓ 看中位数与最近的轮 ✓），
     **把代价告诉用户**（"这一步会让上下文 X 全额重发一次" ✓），由他决定现在做还是等压缩后再做 ✓
2. **这一轮预计超过 ~20 步吗？**
   - 会 ⇒ 每步都要重读一遍上下文 ✗ ⇒ **拆成多个小轮次** ✓（或先压缩再干 ✓）
3. **上下文已经很大（> 50 万 token）而任务是"大重构"吗？**
   - 是 ⇒ 先让 DSH 压缩 ✓ / 拆会话 ✓，别硬扛 ✗

### 事后校准（数据驱动，别凭感觉 ✗）

```bash
# 这一轮为什么贵？（步级 token + 上下文注入 + 归因）
python <toolkit>\dsh\tools\session-cost\session_cost.py --turn <轮次>

# 整体纪律指标（作废次数 / 系统提示重建 / 压缩次数 / 成本当量占比）
python <toolkit>\dsh\tools\session-cost\session_cost.py --audit
```

- 每次遇到"明显比中位数贵的轮"（> 3 倍 ✓）⇒ 跑一次 `--turn N` ✓ 把归因结论写进回复 ✓
- **验收方式**：看 `--audit` 的 ①②③ 三个数字是否下降 ✓（不是靠自我感觉 ✓）

### 诚实边界

- 工具**不算钱** ✗：只给 token 构成与"成本当量"（比例 `--ratio` 默认 `1,0.1,3` 是**假设，未实测** ✗）
- 归因是**相关性** ✗：把"未缓存激增"与其前最近的注入事件关联，不做因果证明 ✓
- 要精确金额 ⇒ 用市场插件 `dsh-cost-meter` ✓
