# 任务列表纪律（task-list-discipline-zh）

## 一句话

> 任务列表**不会自己出现在你眼前** ✗ ⇒ **开工先贴一遍，收尾再贴一遍** ✓
> 想做的事**不在列表里** ⇒ **停下来问** ✗ —— 这条就是防走偏的闸门 ✓

## 为什么需要它（实测，2026-10-16）

用户原话：

> 「我经常找不到任务列表，导致不知道执行到哪里了，后面就走偏了，最后不知道任务列表是什么了」

读 DSH 源码（`app.asar` 里的 `dsh-tool-todo` 与 `dsh-client-ui-tool`）与会话日志，实测四条 ✗：

| 事实 | 后果 |
|---|---|
| 界面上**只有一行工具行**：标题「更新任务清单」✓，摘要 `{done}/{total} 已完成 · <进行中那条>` ✓ | 不显眼 ✗ **没有** `/todos` 命令、**没有**侧边栏面板 ✗ |
| 它折叠在「工作步骤」里 ✗（桌面版默认 `transcriptView = standard` ⇒ `stepGrouping: collapsed`）| 默认**看不见** ✗ |
| `todos` 投影**在下一轮开始时清空** ✗（`turn/end` 保留刚完成的那份 ✓）| 只有"当轮"是活的计划 ✓ ⇒ 过了这轮就得翻记录 ✗ |
| 长对话 / 压缩会把工具行埋掉 ✗ | 更找不到 ✗ |

⇒ 结论：**别指望界面** ✓ —— 把列表写进**对话正文**（agent 的回复里）✓ 那才是用户真正能看到的 ✓

## 五条硬纪律

| # | 纪律 | 反例（就是走偏的样子 ✗） |
|---|---|---|
| ① | **开工先贴**：每轮第一条回复里贴出列表（`x/y` + 进行中那条 + 下一条要做的）| 只说"我开始做了"✗ |
| ② | **变更就更新**：完成/新增/取消一项 ⇒ 立刻 `todo_write` **整个列表**（它是整表替换 ✓ 别攒 ✗）| 干了三件事才更新一次 ✗ |
| ③ | **收尾再贴**：收尾回复里贴**最终列表**（全绿 or 剩余项 ✗）+ 写明"下一轮第一件事"✓ | 只说"做完了"✗ |
| ④ | **闸门**：想做的事**不在列表里** ⇒ 停下来说「这不在列表里：加进去还是先不做？」✗ | 顺手做了 ⇒ **这就是走偏的起点** ✗ |
| ⑤ | **状态如实**：`in_progress` **只在真的在做时留** ✓（用户要它可见，用来知道正在做哪条 ✓）—— **做完就立刻改 `completed`** ✗ 不许挂着不动 ✗；本轮不做的改回 `pending` 并写明"下一轮做" ✓ | 做完不更新 ⇒ 界面上一直"转" ✗ ⇒ 用户分不清"还在跑"和"忘了改" ✗（实测发生过两次 ✓）|

> ⑤ 与 ② 是一体两面 ✓：② 管"别攒" ✓、⑤ 管"别留假状态" ✗
> ⚠️ 界面上那个"转"**只等于列表状态** ✗ —— **不等于进程在跑** ✗
> （判断有没有在跑：问 agent 要 `job_list` ✓；本轮输入框可用 + "正在运行"提示消失 ⇒ 本轮已结束 ✓）

> 状态必须**如实** ✓：没做完的不许标 `completed` ✗（列表一旦说谎，纪律就失效了 ✗）

## 怎么把列表读出来（不依赖界面 ✓）

```bash
# 在 agent-toolkit 仓库里（dsh 专用工具区）
python dsh/tools/todo-peek/todo_peek.py              # 最近会话的最后一次写入（= 当前清单）
python dsh/tools/todo-peek/todo_peek.py --all        # 全部历次写入（看计划怎么变的）
python dsh/tools/todo-peek/todo_peek.py --turn 168   # 指定轮次
python dsh/tools/todo-peek/todo_peek.py --json       # 机器可读
```

- 状态的来源是**会话日志里的事件** `todo/write`（事件溯源 ✓）：
  `~/.dsh/sessions/**/session.v4.jsonl.zstd` ✓（可用 `DSH_SESSIONS_ROOT` 指向别处 ✓）
- 想让工具行**少折叠**（治标 ✓）：设置里找标题 **「工作步骤展示」** ⇒ 选 **详细** 或 **完全展开** ✓
  （治本还是靠上面四条纪律 ✓）

## 交付前自查（可判定 ✓，不是"注意一下"✗）

- [ ] 本轮第一条回复里**有**任务列表吗？
- [ ] 列表状态和实际做的事**一致**吗？（有没有把没做的标成 completed ✗）
- [ ] 有没有**挂着不动**的 `in_progress`？（做完了没改 = 假状态 ✗ —— 用户会以为还在跑 ✗）
- [ ] 有没有做**列表外**的事？有 ⇒ 必须**已经问过**用户 ✗
- [ ] 收尾贴了**最终列表** + **下一轮第一件事**吗？

## 诚实边界

- 技能**不能强制**✗ —— 全靠 agent 自觉执行 ✓；漏了就是漏了 ✗（用户看不到"没贴"这件事 ✗）
- DSH 目前**没有**任务列表面板/命令 ✗（实测：asar 里只有那一行 UI ✓）
- `todo_peek` 只**如实打印**日志里的内容 ✓ 不判断计划好坏、不检查状态真假 ✗
- 列表**属于单个 agent 会话**✗：subagent 有各自的列表 ✓ 不共享 ✗
- **"正在运行 / 后台任务"入口本来就会隐身** ✓（实测源码：`dsh-client-ui-jobs` 挂在
  `conversation.session.header.actions` ✓，且有 `if (visibleCount === 0) return null;` ✗
  ⇒ **本会话没有任何 job 时它整个不渲染** ✗）
  ⇒ 所以"它不见了"通常只是**没有 job** ✓ **不是**插件把它挤掉了 ✗
  ⇒ 想确认有没有在跑：让 agent 跑 `job_list` ✓（它是权威口径 ✓）
