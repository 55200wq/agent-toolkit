## §4 三处角色的新分工（关键决策）

| 位置 | 保留什么 | 不保留什么 |
|---|---|---|
| **`agent-tools/`** | 引擎、模板、自测、文档、**版本** | 项目配置 ✗ |
| **skill（`~/.dsh/skills/…`）** | **规则（SKILL.md）** + 一句"工具在 agent-tools" + 接入命令 | 引擎副本 ✗（避免漂移）|
| **项目（如 sift_match）** | **自己的配置**（`provenance.json` / `selftests.json`）+ 引擎**副本** + 版本戳 `.agent-tools.json` | 通用文档 ✗ |

**为什么项目要留副本（而不是引用 agent-tools 路径）**：
项目可能被单独拷走/换机器 ✓，引用绝对路径会直接失效 ✗ —— 副本 + 版本戳，配合 `--check` 就能既自包含又可查漂移 ✓

**版本戳 `.agent-tools.json`** 长这样：

```json
{"toolkit_version": "0.1.0", "installed_at": "2026-10-16 01:20",
 "files": {"tools/provenance_check.py": "<sha256 前 12 位>", ...}}
```

⇒ `check_project.py` 比对哈希：**被改过**或**落后于 toolkit** 都能报出来 ✓

## §5 契约（命令与退出码）

```bash
# 装进项目（缺配置才生成，绝不覆盖已有配置）
python agent-tools/install/install_into_project.py --project <项目根> [--only provenance]

# 检查漂移（0=一致；1=被改过；2=落后于 toolkit；3=未安装）
python agent-tools/check_project.py --project <项目根>   # 或 install_into_project.py --check
```

| 退出码 | 含义 |
|---|---|
| 0 | 一致 ✓ |
| 1 | 项目里的副本**被本地改过** ✗（要么回退，要么把改动提交回 toolkit ✓）|
| 2 | **落后于 toolkit** ✗（提示重跑安装）|
| 3 | 未安装 ✓ |

## §6 关键点

| # | 关键点 | 理由 |
|---|---|---|
| K1 | **唯一来源在 agent-tools** ✓ | 三处副本必漂移 ✗ |
| K2 | 项目留**副本 + 版本戳**，不引用绝对路径 ✓ | 项目要能被单独拷走 |
| K3 | 安装器**绝不覆盖已有配置** ✗→✓ | 配置是项目口径，覆盖会毁掉项目判断 |
| K4 | 每个工具**自带自测** ✓ | toolkit 自己也得能验证（且用自己检查自己 ✓）|
| K5 | **README 是索引** ✓（新增工具必须登记 ✓）| 用户说"以后还会加更多内容" ⇒ 入口必须唯一 ✓ |
| K6 | skill 只留规则 + 指针 ✓ | agent 读的是规则 ✓，执行的是项目里的副本 ✓ |

## §7 风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | 项目副本逐渐落后 ✗ | 各项目行为不一致 | `--check` 报"落后" + 建议重跑安装 ✓ |

| R7 | 自举检查把自己整挂了 ✗ | CI 全红 | 自测里覆盖"配置缺失/路径不存在"等情形 ✓ |
