# 接入清单：把 agent-toolkit 用到你的项目 / 你的 agent

> 工具集仓库：`https://github.com/<user>/agent-toolkit`（发布时替换 `<user>`）

---

## 一、一行安装（从 GitHub）

```bash
# Linux / macOS / Git-Bash
curl -fsSL https://raw.githubusercontent.com/<user>/agent-toolkit/main/install/install.sh | bash

# Windows / PowerShell
irm https://raw.githubusercontent.com/<user>/agent-toolkit/main/install/install.ps1 | iex
```

带参数（透传给 `install.py`）：

```bash
curl -fsSL .../install.sh | bash -s -- --all --project /path/to/project
# PowerShell: $env:AGENT_TOOLKIT_ARGS="--all --project C:\my\proj"; irm .../install.ps1 | iex
```

## 二、本地克隆安装

```bash
git clone https://github.com/<user>/agent-toolkit.git
cd agent-toolkit

# 装进项目：工具副本 + 配置模板（缺了才写）+ 身份证 + AGENTS 片段 + git 钩子
python install/install.py --project /path/to/your/project --with-agents --with-hook

# 装 skill 给你的 agent
python install/install.py --skills                      # DSH：~/.dsh/skills
python install/install.py --skills --skills-dir <目录>   # 其他 agent
```

## 三、装到哪里（各 agent 的 skills 目录）

| agent | skills 目录 | 命令 |
|---|---|---|
| **DSH** | `~/.dsh/skills/`（Windows：`C:\Users\<你>\.dsh\skills\`）| `python install/install.py --skills` |
| 其他 agent | 它自己的 skills / rules 目录 | `python install/install.py --skills --skills-dir <目录>` |
| 只用规则、不装 skill | —— | 把 `skills/measured-or-flagged-zh/SKILL.md` 拷进它的规则目录 |

> `SKILL.md` 是**通用规则**（任何 agent 都能当规则文档读）；
> 文件头部的 `name/description/whenToUse` 是 DSH 的技能元数据，其他 agent 忽略即可 ✓

## 四、项目里装上之后

```bash
python tools/provenance_check.py --write-assumptions   # 生成"未实测初值"清单
python tools/provenance_check.py --audit               # 看哪些数值还没写来历
python tools/run_all_selftests.py                      # 跑全部自检（自动发现）
```

1. **改配置**：把 `tools/provenance.json` 的 `scan` 改成本项目要扫的文件
   （建议先小范围扫、逐批补标注，**不要一次全开** ✗）
2. **改清单路径**：`assumptions_out` 指向你希望放清单的位置
3. **登记自检**：`tools/selftests.json` 里给每个套件加 `label` / `slow` / `desc`（可选）

## 五、拦住提交（可选，推荐）

`--with-hook` 会装 git 钩子；手动装：

```bash
cp <agent-toolkit>/templates/pre-commit .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

钩子做三件事（都很快，< 2 秒）：数值有没有来历 / 代码与实测档案是否一致 / 标定是否失效。

## 六、漂移检查与更新

```bash
python install/install.py --project <项目根> --check   # 一致0 被本地改1 落后2 未装3
python install/install.py --project <项目根>           # 更新到最新版（配置不会被覆盖 ✓）
```

**约定**：项目里的工具副本**不要手改** ✗ —— 要改就改工具集里的源 ✓

## 七、配置字段速查（provenance.json）

| 字段 | 含义 |
|---|---|
| `scan` | 要扫描的 glob（相对项目根）|
| `exclude` | 排除的 glob（用 `**` 通配）|
| `tags` | 三态/语义的关键字（可多语言，如英文项目用 `basis: measured`）|
| `exempt_name_patterns` | 免检的名字正则（私有状态、时间戳等）|
| `exempt_self_names` | 免检的 `self.x` 名字 |
| `semantic_names` | 语义常量名（状态码等，不算可调）|
| `logic_values` | 免检的逻辑小整数（默认 0/1/2/-1）|
| `assumptions_out` | 未实测清单写到哪 |
| `premise` | 清单顶部声明的前提（换了前提 ⇒ 所有阈值必须重标 ✗）|

标注的**有效范围**：同一行的行尾注释，或**紧邻上方的整行注释** ✓

## 八、它做不到什么（别误解）

| 做不到 | 说明 |
|---|---|
| 判断"值对不对" ✗ | 只保证"有来历或承认没有" |
| 抓回复/文档里的错误断言 ✗ | 靠规则与人工抽查 |
| 扫函数体内的行内字面量 ✗ | 有意收窄（只扫 4 种写法），降低误报 |
| 自动修代码 ✗ | 只报告，决定权在人 |
